Example Firestore Security Rules (required for online mode)

Copy this into Firestore → Rules. These rules require login before reading/writing any data, and restrict the Manage Users menu to admins only.

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    function isSignedIn() { return request.auth != null; }
    function myRole() {
      return exists(/databases/$(database)/documents/users/$(request.auth.uid))
        ? get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role
        : null;
    }
    function isAdmin() { return isSignedIn() && myRole() == 'admin'; }

    match /users/{uid} {
      allow read: if isSignedIn() && (isAdmin() || request.auth.uid == uid);
      allow write: if isAdmin();
    }
    match /tahunAjaran/{doc} { allow read, write: if isSignedIn(); }
    match /siswa/{doc} { allow read, write: if isSignedIn(); }
    match /pembayaran/{doc} { allow read, write: if isSignedIn(); }
    match /pengaturan/{doc} { allow read, write: if isSignedIn(); }
    match /akun/{doc} { allow read, write: if isSignedIn(); }
    match /kegiatan/{doc} { allow read, write: if isSignedIn(); }
    match /pengeluaran/{doc} { allow read, write: if isSignedIn(); }
    match /penerimaanLain/{doc} { allow read, write: if isSignedIn(); }
    match /globalSettings/{doc} { allow read, write: if isSignedIn(); }
    match /publicSummary/{doc} { allow read: if true; allow write: if isSignedIn(); }
    match /auditLog/{doc} { allow read, write: if isSignedIn(); }
  }
}

Introduction

Class Cash Book is a single app for running your class's cash (kas kelas) from end to end: recording each student's monthly dues, printing receipts for parents, logging what the money was spent on, and always knowing the real bank balance.

It works two ways:

  • Connected to Firebase — your data is saved online and synced in real time. This is what lets you share a public report link, add other users, and access your data from any device.
  • Local mode — if there's no internet connection or Firebase isn't set up, the app still works and saves data in your browser only (good for a quick trial, but data won't sync across devices).

The sidebar is your main menu. This guide is grouped the same way: money coming in first, then money going out, then the bank position and account access, then setup.

Logging In

When Firebase is connected, you'll see a login screen first.

  1. Enter the email and password given to you by your class admin/treasurer.
  2. Click Log In.
  3. Forgot your password? Enter your email in the field, then click Forgot password? Send a reset link to the email above.
No account yet? This app doesn't have public sign-up. Ask your class admin to add your email under Manage Users first.

If you log in successfully but see a message that your account has no access yet, it means your email was authenticated but hasn't been added to this class's user list — ask the admin to add you.

School Years

Every school year is its own separate "book." Students, payments, accounts, activities, and expenses for one school year are never mixed with another — but old years are never deleted either; you can switch back and view them anytime.

Switching years: use the School Year dropdown at the top of the sidebar. Whatever you pick there applies to every tab in the app until you change it again.

To create a new school year, click + New School Year in the sidebar, or go to Settings → Manage School Years. You can optionally copy the student list from a previous year — only the student roster copies over, payment history always starts fresh at zero for a new year.

Dashboard

Your at-a-glance summary for the currently selected school year:

Payment Status table below the stat cards is filterable:

  • Month — pick any month within the school year period, not just the current one.
  • Status — All / Unpaid only / Paid only.
  • Search — filter by student name.
Tip: switch Status to Unpaid only to instantly get your "who still needs to pay" list for any month.

Student Records

This is your class roster for the selected school year.

  1. Click + Add Student.
  2. Fill in roll number, full name, parent/guardian name, and phone/WhatsApp number (all optional except name).
  3. Special Dues Amount is optional — leave it blank if the student pays the same default amount as everyone else (set in Settings). Only fill it in if this student's dues are different.
  4. Click Save.

Use the search box to find a student by name. Click ✎ to edit, or 🗑 to delete.

Note: a student can't be deleted if they already have payment history — delete their payment records first (in Payment Entry's history table) if you really need to remove them.

Payment Entry

This is where you record a student paying their monthly dues.

  1. Select the student from the dropdown.
  2. Click each month the student is paying for — a highlighted chip means already paid and can't be selected again; select one or several months in a single transaction (e.g. paying 3 months at once).
  3. Set the payment date, method (Cash, Transfer, or QRIS), and an optional note.
  4. Check the Total Amount preview, then click Save Payment.
Tip: the payment period always runs July → June regardless of calendar year.

Payment History below the form lets you search, and from there: ✎ Edit a payment's months/amount/date/method/note, 🗑 Delete it (the related months go back to unpaid), or jump straight to 🖨 Print Receipt.

Print Receipt

Find any payment transaction (search by student name) and generate a proof-of-payment receipt for parents.

ButtonWhat it does
🖨 PrintOpens the browser's print dialog with a formatted receipt
🖼️ ImageDownloads the receipt as a PNG image
📄 PDFDownloads the receipt as a PDF file
💬 WAOpens WhatsApp with a pre-written message to the parent's saved phone number

The receipt includes school/class name, student and parent name, months paid, period, amount, method, date, receipt number, and signature lines. A student who has paid the full school year gets a "PAID · 1 YEAR · CLASS" stamp automatically.

Report Summary

The full-class view of who has paid which months — a 12-column matrix with every student as a row, plus Total Collected, Payment Completeness %, and Paid Slots.

Click 🖨 Print Report to print the whole matrix — it automatically switches the page to landscape (since the table is wide) and switches back afterward.

Sharing With Parents (Public Link)

At the bottom of Report Summary is Share With Parents (Public Link) — creates a link anyone can open, no login required, showing a safe read-only snapshot.

Privacy by design: the public link never includes phone numbers or parent names — only student names, monthly paid/unpaid status, total collected, and the bank balance.
  1. Click Publish / Update Public Link.
  2. Copy the link and share it in your class group.
Important: this is not live. It only shows data as of your last Publish click — click it again after new payments if you want parents to see updated numbers.

Requires Firebase won't work in local mode.

Chart of Accounts

Found in Settings. The list of expense categories your Expense Ledger is grouped by — e.g. 6900-00-011 — Class Supplies.

  1. Click + Add Account.
  2. Enter an account code and a name.
  3. Click Save.
An account can't be deleted while any Activity is linked to it, and each account code must be unique within the school year.

Activities

Also in Settings, right below Chart of Accounts. Activities are what you actually pick when logging an expense — each one is mapped to one account above.

  1. Click + Add Activity (need at least one account first).
  2. Name the activity and choose its linked account.
  3. Click Save.

Setting a default: click the ⭐ icon next to the activity you use most often. It gets a Default badge and is pre-selected automatically in Expense Entry. The first activity you create for a school year becomes default automatically.

An activity can't be deleted while it already has expense records.

Expense Entry

Where you log class operational spending.

  1. The Activity dropdown is pre-filled with your default — change it if needed.
  2. Enter the date, amount, and a short description.
  3. Click Save Expense.

A reference number (e.g. CD000007) is generated automatically. Expense History below lets you search, edit, or delete past entries.

Expense Ledger

A detailed "general ledger" style report (Buku Besar), grouping every expense by account with a running balance.

  • Each account gets its own section: starting balance, every transaction with a running total, and an ending balance.
  • 🖨 Print Report prints the full ledger.
  • 🖼️ Save as Image (HD) downloads a high-resolution PNG of the whole report.

Cash Balance

The single running bank account (e.g. Bank Mandiri) that combines money in and money out into one real balance:

Current Balance = Opening Balance + All Payments − All Expenses

Setting the opening balance — do this once, entering whatever the account balance already was before you started using this app. Every payment and expense afterward (in any school year) is added or subtracted automatically.

Carries over across school years: unlike almost everything else in the app, this balance is not reset per school year — it's one continuous account.

Cash Flow Mutation is a chronological list of every payment and expense across all school years with a running balance. 🖨 Print Report and 🖼️ Save as Image (HD) work the same as the Expense Ledger.

Manage Users

Admin only — add other teachers or treasurers who need access.

  1. Enter their email and a temporary password (at least 6 characters).
  2. Choose their role: Treasurer (enter/view data) or Admin (also manage users).
  3. Click + Add User.
  4. Share the email/password privately — they can change the password via "Forgot password" on the login screen.

Click Revoke Access to remove someone's access to this class's data (their login account itself still exists).

Settings

Everything configuration-related, top to bottom:

  • Class Identity — school name, class name, default dues amount, homeroom teacher, treasurer name.
  • Manage School Years — see School Years.
  • Chart of Accounts and Activities — see above.
  • Firebase Connection and Firestore security rules.
  • Backup / Restore.

Firebase Connection

The app comes with a Firebase project built in by default — most classes never need to touch this. It's only relevant to connect your own separate Firebase project instead.

  1. Paste your own Firebase config (JSON) into the text box.
  2. Click Connect to This Config — the page reloads and connects to your project.
  3. Restore Default Config goes back to the built-in project.
  4. Force Local Mode temporarily disables Firebase on this device for testing, without affecting the online database.

Security Rules — whenever a new feature needing new data is added, its Firestore rules need publishing in the Firebase Console, or you'll see "Missing or insufficient permissions" errors. The exact rules text to copy is always shown in Settings.

Still seeing permission errors after publishing? Wait 30–60 seconds for the rules to propagate, then fully close/reopen the tab (or hard refresh).

Backup & Restore

Local mode only

  • ⬇ Download Backup (.json) — saves everything: school years, students, payments, accounts, activities, expenses, and the bank balance.
  • ⬆ Restore from Backup — overwrites current local data with a previously downloaded file.
Restoring completely replaces all current local data — there's no undo.

If connected to Firebase, use Firebase Console → Firestore → Export instead.

Tips & Troubleshooting

"Missing or insufficient permissions" errors — the Firestore Security Rules in Settings haven't been published yet (or a new one was added since your last publish). Re-copy and re-publish, wait a minute, then hard-refresh.

Sidebar shows "Local mode (not connected)" — either Firebase couldn't be reached, or someone clicked Force Local Mode on this device. Check Settings → Firebase Connection for the status message.

A print looks empty or has an extra blank page — reload the page and try the Print button again; each report builds its own printable copy right before printing.

Numbers don't match what I expect — Dashboard and Report Summary are scoped to the currently selected school year only. Cash Balance is the exception — it always reflects all school years combined.

I changed an Activity's linked account — existing expense history moves with it; the Expense Ledger groups by account as it stands today, not as it was when the expense was recorded.
